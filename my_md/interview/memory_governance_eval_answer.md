# Memory Governance Evaluation Interview Answer

我没有只做一个新旧版本对比，而是把记忆回答链路拆成多层剖面。

P1 只测三路召回和 RRF 融合，P2 加候选治理，P3 单独加结构化证据但不加回答契约，P4 再加入完整回答约束。这样我能解释每一层到底提升了什么，而不是只报一个黑盒准确率。

数据集由 Codex 生成，但生成后先做证据依赖图自检，检查循环依赖、悬空引用、旧记忆误召回和 expected/forbidden 冲突。同时我还会对 80 条 case 做 20% 随机人工语义审查，也就是抽 16 条，确认问题、记忆和预期答案在人类常识下成立。如果发现超过 2 条语义荒谬样本，就不放行这批数据，而是调整生成器模板和场景权重后整批重生成。

真实执行时使用 DeepSeek，并固定 temperature、top_p 和 seed 做主评测。评分上先用确定性规则守住 forbidden 和旧值泄露，再只对模糊边界用异源语义仲裁。

因此 `37.5% -> 97.5%` 是同一张表里从基础三路召回到完整治理链路的结果；`98.75%` 是后续 safe-version system-path 的独立稳定性验证，不混在同一个因果结论里。
