# 320 Case 原始记忆基线增强评测

本文记录 320 case comprehensive 离线评测结果。评测目标是回答一个更明确的问题：

```text
在原始 memory 已经开启的基础上，额外打开某个增强模块，能多召回多少目标记忆，少漏召多少目标记忆？
```

## 评测边界

- 样本规模：320 case，其中 common 160，hard 160。
- 目标记忆总数：640 条。
- 评测方式：离线 deterministic eval，不调用真实 LLM，不读写生产 memory DB。
- 主基线：`memory_base` / `chain_memory_base`，表示原始记忆行为。
- 控制组：`off` / `chain_off`，表示关闭增强控制组，不作为主基线。
- 数据来源：`/tmp/akashic-memory-320-baseline-plus/` 下的 `memory_quantitative_uplift_eval.json` 和 `memory_quantitative_chain_eval.json`。

## 结论

1. 原始记忆基线已经很强，320 case 上召回率为 `98.12%`，所以不能再用 `off` 当主基线夸大增强收益。
2. 三路召回是当前最明确的正向增强：从 `628/640` 提升到 `640/640`，多命中 12 条，召回率提升 1.88 个百分点。
3. 图谱召回也有正向贡献：从 `628/640` 提升到 `638/640`，多命中 10 条，召回率提升 1.57 个百分点。
4. 重排与注入治理、版本链与溯源在单模块表里偏低，但在组合链路里能够跟随三路召回维持 `640/640`，说明它们更适合放在链路后段做治理，而不是单独当召回模块评价。
5. 睡眠巩固在当前回答召回指标下表现为下降，这是符合预期的风险信号：睡眠巩固是库级维护能力，应该用重复合并、低价值清理、token 节省和关键记忆保留率单独评价，不能只用即时召回来判定。
6. 全开组合当前低于原始记忆基线，说明增强模块还不能简单全部 active 化，需要按场景路由打开。

## 后续动作

- 将三路召回、图谱召回、重排与注入治理作为回答召回链路的优先 active 候选。
- 将写入价值治理和睡眠巩固从回答召回表中拆出去，分别使用写入治理表和记忆库卫生表评测。
