# 320 Case 原始记忆基线增强评测

本文记录 320 case comprehensive 离线评测结果。评测目标是回答一个更明确的问题：

```text
在原始 memory 已经开启的基础上，额外打开某个增强模块，能多召回多少目标记忆，少漏召多少目标记忆？
```

## 评测边界

- 样本规模：320 case，其中 common 160，hard 160。
- 目标记忆总数：640 条。
- 评测方式：离线 deterministic eval，不调用真实 LLM，不读写生产 memory DB。
- 主基线：`memory_base` / `chain_memory_base`，表示原始记忆行为。
- 控制组：`off` / `chain_off`，表示关闭增强控制组，不作为主基线。
- 数据来源：`/tmp/akashic-memory-320-baseline-plus/` 下的 `memory_quantitative_uplift_eval.json` 和 `memory_quantitative_chain_eval.json`。

## 结论

1. 原始记忆基线已经很强，320 case 上召回率为 `98.12%`，所以不能再用 `off` 当主基线夸大增强收益。
2. 三路召回是当前最明确的正向增强：从 `628/640` 提升到 `640/640`，多命中 12 条，召回率提升 1.88 个百分点。
3. 图谱召回也有正向贡献：从 `628/640` 提升到 `638/640`，多命中 10 条，召回率提升 1.57 个百分点。
4. 重排与注入治理、版本链与溯源在单模块表里偏低，但在组合链路里能够跟随三路召回维持 `640/640`，说明它们更适合放在链路后段做治理，而不是单独当召回模块评价。
5. 睡眠巩固在当前回答召回指标下表现为下降，这是符合预期的风险信号：睡眠巩固是库级维护能力，应该用重复合并、低价值清理、token 节省和关键记忆保留率单独评价，不能只用即时召回来判定。
6. 全开组合当前低于原始记忆基线，说明增强模块还不能简单全部 active 化，需要按场景路由打开。

## 后续动作

- 将三路召回、图谱召回、重排与注入治理作为回答召回链路的优先 active 候选。
- 将写入价值治理和睡眠巩固从回答召回表中拆出去，分别使用写入治理表和记忆库卫生表评测。
- 下一轮真实 LLM 测评不应跑所有模块全开，而应优先验证：
  - `chain_memory_base`
  - `chain_tri_retrieval`
  - `chain_graph_retrieval`
  - `chain_rerank_injection`
  - `chain_all_on`

公式说明：

- 相对召回率提升 = 召回率变化百分点 / 原始基线召回率。
- 相对基线漏召减少率 = 漏召减少数 / 原始基线漏召数。
- 当相邻上一步已经没有漏召时，相邻漏召减少率显示为 `N/A`，避免把后续退化误写成 `0%`。
- 负数表示比基线漏召更多，可能小于 `-100%`；例如重排与注入治理单独开启时不是扩召回入口，候选池不足会放大漏召，因此要放到三路和图谱召回之后评价。

### V2 结论

1. 更大测试集上，原始记忆基线仍然很强：`1978/2000`，召回率 `98.9%`。
2. 三路召回是最稳定的回答侧正向增强：补齐全部 22 条漏召回，达到 `2000/2000`；相对召回率提升 `1.1122%`，漏召回减少 `100.0%`。
3. 图谱召回仍然有正向贡献：相比原始记忆多命中 16 条，相对召回率提升 `0.8089%`，漏召回减少 `72.7273%`，但比三路召回少 6 条。
4. 重排与注入治理不适合单独作为召回模块评价；但在纯回答组合链路中，它能跟随三路和图谱保持 `2000/2000`，说明它更适合放在检索之后做候选治理。
5. 版本链与溯源在组合链路中仍保持高召回，最终为 `1998/2000`；单模块表偏低，说明这类能力更偏证据治理和版本选择，不应只看单项召回。
6. 回答链路全开相比原始记忆多命中 20 条，相对召回率提升 `1.0111%`，漏召回减少 `90.9091%`，但比三路召回单项少 2 条；因此可以证明 answer-only 组合有正向收益，但当前最强召回路径仍是三路召回，后续需要继续优化组合权重。
7. 本离线计数报告只证明“目标记忆有没有被召回”。回答正确性、证据命中、噪声控制和上下文成本需要后续在线 shadow / agent dry-run 提供真实 LLM 输出、source_ref / grounding trace、注入条目明细和 token / latency evidence。

面试时不要把所有模块都说成“提升召回率”的模块。更准确的说法是：三路召回和图谱召回负责扩大候选覆盖，重排、注入治理、版本链和溯源负责候选治理与证据可信度。

| 三路召回 | `2000/2000`，多命中 `22` 条，漏召回减少 `100.0%` | 这是当前最直接的召回增强。它把原始记忆漏掉的 22 条全部补齐，说明语义、关键词、溯源三路融合能提高覆盖率。 |
| 图谱召回 | `1994/2000`，多命中 `16` 条，漏召回减少 `72.7273%` | 图谱召回对实体别名、模糊指代和关系跳转有效，但单独看略低于三路召回。 |

| 版本链与溯源 | 单独 `1000/2000`；组合后 `1998/2000` | 它主要解决旧版本误用、来源缺失、跨 scope 风险和证据可信度，不负责扩大召回池。单独看召回会低估它，组合后基本不损伤召回。 |
| 回答链路全开 | `1998/2000`，多命中 `20` 条 | 纯回答链路全开有正向收益，但比三路召回单项少 2 条，说明组合权重和路由仍有优化空间。 |

可背诵版本：

```text
我们没有用关闭记忆作为基准，因为那会夸大收益。我们用原始 memory 作为基线，在 1000 个 case、2000 条目标记忆上测。原始 memory 已经能召回 1978 条，召回率 98.9%。

在这个基础上，三路召回补齐全部 22 条漏召回，达到 2000/2000，漏召回减少 100%，是当前最直接的召回增强。图谱召回能提升到 1994/2000，漏召回减少 72.7273%，说明它对实体别名、模糊指代和关系跳转有效。

重排与注入治理、版本链与溯源不能单独按召回率评价。它们不是用来扩大召回池的，而是做候选排序、去噪、来源校验、版本选择和跨 scope 风险控制。单独开启时召回会下降，但放到三路召回和图谱召回后面，完整回答链路仍能保持 1998/2000 的高召回。

所以结论是：三路召回和图谱召回负责找得更多，重排、注入治理、版本链和溯源负责用得更准、更可信。

这份离线表只回答“有没有找回来”。回答正确性、证据命中、噪声控制和上下文成本要进入下一阶段在线 shadow 或 agent dry-run，用真实 LLM 输出和 trace 数据评价。
```
